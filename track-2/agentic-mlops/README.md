# Agentic MLOps — Week 17 (Track B)

Self-checking RAG research assistant upgraded with production MLOps practices:
**uv** for environment management, **MLflow** for experiment tracking + agent tracing,
and **Evidently AI** for LLM regression testing across 3 evidence-based prompt versions.

Built on the Week 15 baseline (`RagTool`, TF-IDF retrieval) and Week 16 single-agent loop
(decide → act → observe, max-iterations stop). This week adds versioned prompts, structured
traces, a 12-query golden regression set, and a FastAPI serving layer.

## Setup with uv

Requirements: `uv` 0.12+ and Python 3.11 (pinned via `uv sync --python 3.11`).

```bash
cd agentic-mlops

# 1. Install locked dependencies (creates .venv + verifies uv.lock)
uv sync --python 3.11

# 2. (Optional) live LLM decisions via Groq/OpenAI; offline deterministic
#    policies run without any key.
cp .env.example .env
# edit .env: GROQ_API_KEY=...  (default model llama-3.3-70b-versatile)

# 3. Sanity check
uv run python src/agent.py "What is the refund policy?" v3
```

How `uv` is used here:

| Task | Command |
|---|---|
| Install | `uv sync --python 3.11` (reads `pyproject.toml` + `uv.lock`) |
| Run agent | `uv run python src/agent.py "<q>" v3` |
| Run evals | `uv run python -m src.evaluate --all` |
| Serve API | `uv run uvicorn src.app:app --port 8000` |
| Add dep | `uv add <pkg>` (updates `pyproject.toml` + `uv.lock`) |

`pyproject.toml` declares `fastapi`, `uvicorn[standard]`, `mlflow`, `evidently`,
`pydantic`, `python-dotenv` (requires-python `>=3.11,<3.13` for MLflow/Evidently
compatibility). `uv.lock` (393 KB, 142 packages) is committed so installs are reproducible.

## MLflow experiment tracking

Backend: SQLite (`mlflow.db`) — the plain `./mlruns` file store is in maintenance
mode in MLflow ≥ 3, so `src/tracker.py` defaults to `sqlite:///mlflow.db`.

Per prompt version, `src/evaluate.py` opens `prompt_v{1,2,3}` runs and logs:

- **Params:** `prompt_version`, `model_name`, `temperature`, `top_k`, `chunk_size`, `max_iterations`
- **Metrics:** `token_usage` (avg/question), `latency` (avg s), `task_completion_score`,
  `evidently_pass_rate`, `correctness_avg`, `preservation_avg`
- **Artifacts:** prompt text (`prompts/prompt_v*.txt`), all 12 agent traces (JSON),
  evaluation report (`evaluations/eval_v*.json` + `.md`), Evidently input CSV / HTML when available

```bash
uv run python -m src.evaluate --all   # logs v1, v2, v3 runs
uv run mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
# open http://localhost:5000 → experiment "agentic-mlops"
```

## Agent tracing

Every `run_agent()` call emits a structured trace (saved to `traces/trace_{v}_{ts}_{slug}.json`
and logged to MLflow). Schema per step:

```json
{
  "step_number": 1,
  "tool_selected": "rag_search | none (answer) | none (clarify)",
  "tool_arguments": {"query": "...", "top_k": 5},
  "raw_tool_result": {"ok": true, "results": [{"doc_id": "doc1", "score": 10.0, "text": "..."}]},
  "reasoning": "V3: weak evidence (best=0); retry with keywords+synonyms.",
  "decision": "continue | stop"
}
```

Top-level fields: `total_iterations`, `termination_reason`
(`answered | clarified | abstained | max_iterations`), `iterations`, `tool_calls`,
`tokens`, `latency_s`, `history`, `config`, `prompt_version`.

## Prompt version comparison (evidence-based)

### V1 — naive baseline (`prompts/prompt_v1.txt`)

- Raw-question search once, **always answer**, no clarification, hallucinate from
  "general knowledge" on empty evidence.
- Config: temp 0.7, top_k 3, chunk 300, max_iter 2.

**Why V1 failed (traces `trace_v1_*.json`):** 8/12 passed (67%).
`paraphrase-refund` ("money back" vs "refund") scored 0 → V1 answered
`"Based on general knowledge..."` (fabrication). `vague` ("Hi") same hallucination
instead of clarifying. `compositional` cited only `doc6`, missing the 30-day fact.
`paraphrase-password` ("Forgotten credentials, locked out") likewise had zero
keyword overlap → hallucination.

### V2 — abstention + keyword retry (`prompts/prompt_v2.txt`)

- Change: keyword extraction retry (drop stopwords), abstain/clarify on tool error
  or persistent weak evidence (`best < 2.0`), vague-query guard, JSON actions.
- Config: temp 0.3, top_k 5, chunk 300, max_iter 3.

**What improved:** `vague` now clarifies (9/12, 75%); tool-failure runs abstain
instead of fabricating.
**Why V2 still failed (traces `trace_v2_*.json`):** keyword-only reformulation has
no synonyms, so `money back → "money back"` still scores 0 → clarifies on an
answerable query (soft failure). Same for `forgotten/locked out → "forgotten
credentials locked out..."`. `compositional` retrieves `doc6` only and stops after
one retry — the 30-day fact is never gathered.

### V3 — production (`prompts/prompt_v3.txt`)

- Changes (all traceable to V2 failures):
  1. **Synonym expansion** (`SYNONYM_MAP` in `agent.py`, token-based, not substring):
     `money/back → refund return policy`, `forgotten/locked → reset password`, etc.
  2. **Multi-iteration compositional coverage**: when a return+warranty question has
     only one of `{doc1, doc6}`, keep searching for the missing side and cite both.
  3. **Retrieval hygiene**: top_k 5, chunk 500 (full facts), temp 0.0, max_iter 5.
- Config: temp 0.0, top_k 5, chunk 500, max_iter 5.

**Result:** 12/12 passed (100%). Paraphrases resolve via expansion
(`money back refund return policy → doc1`, score 5.0+); compositional cites
`Based on doc1: ... Based on doc6: ...`; vague/tool-error still clarify/abstain safely.

| version | pass | fails |
|---|---|---|
| v1 | 8/12 (67%) | paraphrase-refund, paraphrase-password, vague, compositional |
| v2 | 9/12 (75%) | paraphrase-refund, paraphrase-password, compositional |
| v3 | 12/12 (100%) | — |

## Evidently regression testing

Dataset: `REGRESSION_DATASET` in `src/evaluate.py` — 12 queries (8 direct, 2 paraphrases
with zero keyword overlap, 1 vague, 1 compositional), each with `question` + `golden`.

```bash
uv run python -m src.evaluate --all          # all three versions
uv run python -m src.evaluate --version v3   # single version
```

Per (response, golden) pair the judge records:

- **correctness** — golden-keyword coverage + doc-citation check (compositional
  requires both `doc1` and `doc6`; wrong-doc citation caps at 0.3–0.4)
- **information preservation** — token-F1 between response and golden
- **pass/fail** — `correctness ≥ 0.5 and preservation ≥ 0.2` (clarify items judged
  on correctness alone)
- **overall % passed** — logged to MLflow as `evidently_pass_rate` (+ `task_completion_score`)

Evidently integration (`try_evidently_suite`): when the installed `evidently` exposes
`TestSuite`, an `evidently_report_{v}.html` is generated and logged; the per-row
`evidently_input_{v}.csv` audit table is always written to `evaluations/`. With no
LLM key the deterministic keyword/F1 judge (same Correctness/Preservation semantics)
is used so `uv sync` + `evaluate` work fully offline — the report notes which path ran
(see `evaluations/eval_v*.json → evidently.detail`).

## Results and best prompt selection

```text
| version | pass_rate | correctness | preservation | avg_tokens | avg_latency |
| v1      | 67%       | 0.69        | 0.59         | 948        | 0.000s      |
| v2      | 75%       | 0.78        | 0.60         | 1620       | 0.000s      |
| v3      | 100%      | 0.99        | 0.73         | 2334       | 0.000s      |
```

**Best prompt: V3.** It is the only version at 100% regression pass rate with the
highest correctness (0.99) and preservation (0.73). Cost: ~2.5× the tokens of V1
(more retries, larger chunks) — justified for grounded, non-fabricating answers.
V2 is a safe fallback when latency/token budget matters (75%, fixes fabrication but
fails paraphrases). V1 is kept only as the naive baseline.

